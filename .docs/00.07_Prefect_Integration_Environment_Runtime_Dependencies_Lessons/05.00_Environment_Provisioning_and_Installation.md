# 05 — Environment Provisioning and Installation

## 1. Objective

Describe the supported scripts and exact provisioning behavior for creating or updating a GPWCF Python environment from the local bundle.

## 2. Preflight

Before installation:
1. Confirm the target is the GPWCF project environment or a newly allocated GPWCF-only path.
2. Run Verify-GpwcfBundle.ps1.
3. Confirm the target Python reports CPython 3.15.1 / Windows / AMD64.
4. Do not select a different SMRB project's interpreter.
5. Do not overwrite an existing environment using the environment factory.

## 3. Verify the bundle

PowerShell:

$bundle = "C:\Trading\Projects\Shared_Memory_Reqgion_Broker\SMRB\.dependencies\SMRB.GenericPipelineWorkflowComponentsFramework\python"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$bundle\scripts\Verify-GpwcfBundle.ps1"

Expected result includes a successful integrity message for 109 artifacts and the 105-distribution Prefect closure.

## 4. Install into an existing explicit environment

Example for the current GPWCF environment:

$projectPython = "C:\Trading\Projects\Shared_Memory_Reqgion_Broker\SMRB\SMRB.GenericPipelineWorkflowComponentsFramework\.env\Scripts\python.exe"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$bundle\scripts\Install-GpwcfDependencies.ps1" -TargetPython $projectPython -Profile development

The current project environment was provisioned using the development profile. Its observed versions are Prefect 3.9.2 and pytest 9.2.0; pip check passed.

The installer only acts on the TargetPython supplied. It does not locate or mutate other environments.

## 5. Create a new environment from the shared runtime

Choose a new path that does not already exist:

$target = "C:\Trading\Projects\Shared_Memory_Reqgion_Broker\SMRB\SMRB.GenericPipelineWorkflowComponentsFramework\.venv-prefect-shared"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$bundle\scripts\New-GpwcfEnvironment.ps1" -TargetEnvironmentPath $target -Profile development

The factory validates the shared CPython runtime, creates the venv, and invokes the installer. It refuses to overwrite an existing path.

Do not use the example target if it already exists. Select a fresh path and inspect it first.

## 6. Profile selection

| Profile | Installs | Typical use |
|---|---|---|
| prefect | Prefect runtime | Run Prefect integration |
| test | pytest | Core/test-only environment |
| build | setuptools | Build package |
| development | Prefect + pytest | GPWCF development and integration tests |
| all | Prefect + pytest + setuptools | Full local development/build toolset |

The environment factory supports prefect, development and all. The installer supports all five profiles.

## 7. Installer guarantees

Install-GpwcfDependencies.ps1:
- validates the target executable and target runtime;
- resolves only the profile's lock files;
- installs from the local wheelhouse only;
- enforces binary-only artifacts and hashes;
- runs pip check;
- verifies Prefect, pytest and/or setuptools versions for profiles that include them.

A failed installation throws rather than reporting success. If the factory has already created a new environment when provisioning fails, it leaves the partial environment for diagnosis.

## 8. Existing .env migration warning

The current .env was deliberately preserved and points to C:\Python315 in pyvenv.cfg. The environment factory uses the shared runtime under SMRB\.dependencies\PayloadDescriptionGenerator\CPython-3.15.1. These are distinct provenance facts.

Do not manually edit pyvenv.cfg to make the existing environment appear to have been created from the shared runtime. If migration is required, create a new environment, verify it, switch the project interpreter configuration deliberately, and only then retire the old environment.

## 9. Cleanup

Temporary verification environments created for qualification were removed after successful verification. A failed environment-factory run is intentionally preserved for diagnosis. Do not indiscriminately delete .env or other environments as part of routine bundle verification.
