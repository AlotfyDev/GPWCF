# 04 — Wheelhouse and Offline Artifact Preparation

## 1. Objective

Record how the dependency bundle retains installable artifacts, how source-only compatibility was handled, and how offline integrity is verified.

## 2. Bundle layout

The project-specific dependency bundle is:

SMRB\.dependencies\SMRB.GenericPipelineWorkflowComponentsFramework\python

It contains:
- locks — hash-pinned profile requirements;
- wheelhouse — retained package artifacts;
- reports — pip resolution reports;
- manifests — machine-readable package/artifact inventory;
- scripts — environment, install, verification and manifest tooling;
- README.md — bundle usage and governance notes.

The bundle is solution-root scoped and does not create a project-local dependency folder.

## 3. Artifact inventory

The verified inventory contains 109 artifacts:
- 108 wheel files;
- one retained source archive;
- total wheelhouse size approximately 39.77 MiB.

The Prefect closure contains 105 distributions. The overall artifact count is not the same as the Prefect package count because test/build profiles and source/wheel representations are also retained.

## 4. PyYAML source-to-wheel handling

PyYAML 6.0.3 was resolved from a source archive. A CPython 3.15.1 / Windows x64 wheel was built locally using the retained setuptools 84.2.1 wheel in a temporary build environment.

Both the source archive and locally built wheel are represented in the lock by hashes. Normal offline installation is constrained to binary artifacts with --only-binary=:all:, so it consumes the built wheel rather than trying to compile the source archive during installation.

Build-PyYAMLWheel.ps1 records the repeatable local rebuild procedure. The source archive is retained as provenance; the wheel is the binary installation artifact for the qualified target.

## 5. Integrity verification

Verify-GpwcfBundle.ps1:
1. loads the dependency-bundle manifest;
2. checks every listed artifact exists;
3. calculates SHA-256 for each artifact;
4. compares actual and manifest hashes;
5. checks all three lock files exist;
6. verifies Core runtime dependencies remain empty;
7. verifies the optional Prefect pin remains prefect==3.9.2.

The latest verification completed successfully:
- 109 artifacts verified;
- Prefect runtime closure: 105 distributions.

## 6. Platform compatibility

This wheelhouse is qualified for Windows AMD64 / CPython 3.15.1 only. Compiled wheels encode interpreter ABI and platform tags. Reuse on Linux, ARM64, or another CPython minor/ABI requires a separately resolved and verified artifact set.

## 7. Operational lessons

- Keep the source archive and generated wheel together when the wheel was locally built from source.
- Never bypass hash checking to make an offline installation pass.
- Do not use a wheelhouse as a generic cross-platform package cache.
- Regenerate the manifest after any intentional artifact change, then run the verifier.
- A hash match establishes byte integrity against the manifest, not upstream authenticity, license compliance, or supply-chain approval.
