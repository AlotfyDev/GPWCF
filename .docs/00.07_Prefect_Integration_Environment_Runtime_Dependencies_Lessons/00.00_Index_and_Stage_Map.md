## 1. Purpose

This folder records the environment and runtime work required to provision, build, test, and operate the optional Prefect integration for GPWCF. It is an implementation/operations record, not a replacement for the GPWCF architecture contracts.

The documents distinguish:
- the shared CPython runtime from project virtual environments;
- Core runtime dependencies from optional Prefect integration dependencies;
- build-backend dependencies from application runtime dependencies;
- Prefect operational state/identities from GPWCF domain results/identities;
- technically verified preparation from formal release approval.

## 3. Execution sequence

1. Establish target platform and architectural boundaries (01).
2. Locate/qualify the shared runtime and determine which environment is being provisioned (02).
3. Resolve dependency closures and produce reviewable lock files (03).
4. Retain offline artifacts and verify hashes (04).
5. Provision only the explicitly targeted GPWCF environment (05).
6. Build the package with a build-only backend and inspect wheel metadata (06).
7. Run integrity, isolation and test verification (07).
8. Preserve Prefect-specific operational lessons and E2E assumptions (08).
9. Use the maintenance runbook for any future dependency refresh (09).
10. Close formal release and governance gates before declaring a releasable distribution (10).

## 5. Evidence discipline

The dependency bundle manifest is the machine-readable artifact inventory and hash authority. Its current status is offline-verified. This document set records the human-readable interpretation and known limitations.

A statement marked **verified** means a concrete command or test was run and its result observed. A statement marked **configured** means the corresponding metadata/script exists but is not itself proof of every deployment scenario. **Pending** means no approval or qualification is claimed.
