# 02 — Python Runtime and Environment Topology

## 1. Objective

Record the Python runtime target, its provenance, the virtual-environment topology, and the important difference between the existing GPWCF .env and environments created by the bundle's environment factory.

## 2. Qualified target

| Attribute | Target |
|---|---|
| Operating system | Windows |
| Architecture | AMD64 / x64 |
| Implementation | CPython |
| Version | 3.15.1 |
| Prefect | 3.9.2 |
| pytest | 9.2.0 |
| Build backend | setuptools 84.2.1 |

The bundle is platform-specific. Compiled wheels in the wheelhouse must not be assumed compatible with another OS, CPU architecture, or CPython ABI.

## 3. Shared interpreter source

The bundle manifest identifies the shared runtime at:

SMRB\.dependencies\PayloadDescriptionGenerator\CPython-3.15.1\python.exe

The bundle's New-GpwcfEnvironment.ps1 resolves this runtime relative to the solution dependency root. Before creating an environment it checks that the runtime reports exactly:

3.15.1 | Windows | AMD64

The runtime is reused, not downloaded or installed by the GPWCF dependency scripts. The GPWCF project does not own or distribute this interpreter.

## 4. Virtual environments are separate from the interpreter

A venv is a package-isolation environment built on a base Python runtime. It is not itself a standalone interpreter distribution. A venv's pyvenv.cfg records the base interpreter location used at creation.

The bundle provides a controlled way to create a new environment from the shared CPython runtime. It refuses to overwrite an existing target path.

Its observed installed versions are:

pip check returned: No broken requirements found.

**Important:** This existing .env was preserved and was not recreated from the shared runtime. Its base interpreter reference remains C:\Python315. It is package-isolated (system site packages disabled), but its provenance is not the shared CPython folder referenced by the new-environment script.

## 6. New environment path

New-GpwcfEnvironment.ps1:
1. Resolves the shared CPython runtime.
2. validates version, operating system, and architecture.
3. refuses to proceed if the requested target environment already exists.
4. creates a venv using the shared runtime.
5. calls Install-GpwcfDependencies.ps1 for the selected profile.
6. stops with a diagnostic if provisioning fails. If dependency provisioning fails after venv creation, the partial environment is preserved for diagnosis rather than silently deleted.

A temporary environment created through this script was tested with an offline Prefect install, Prefect import/version verification and pip check. That temporary environment was subsequently removed.

## 7. Recommended choice

- Continue using the existing .env for current project work unless a deliberate environment migration is approved.
- For a newly provisioned environment whose base runtime must be the shared CPython copy, use New-GpwcfEnvironment.ps1 with a new, non-existing target path.
- Do not point the script at .env while it exists; overwrite is intentionally refused.
- Do not assume changing the pyvenv.cfg text manually migrates an environment. Recreate a new venv from the intended interpreter and reinstall the selected lock profiles instead.

## 8. Environment reproducibility evidence

The bundle's temporary clean environment creation was verified. The current project .env health was separately verified. These are two distinct evidence statements and must remain distinct in future reports.
