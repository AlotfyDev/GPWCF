# 5. PHASE-03 Architecture Decisions and Remaining Gates

The following decisions are reflected in the accepted PHASE-03 artifacts as of 2026-11-09.

| Concern | Accepted disposition | Remaining constraint |
|---|---|---|
| Step Result | Distinct logical result module physically nested in the Step Aggregate package | Optional result-slot typing remains a contract gate |
| Conditional Step Error Model | Deferred; not part of baseline Core | Requires generic error-vocabulary and dependency-closure approval |
| Architectural Guidance | Documentation/conformance material only | No runtime package or manager |
| Consumer | External consumer project | Must use GPWCF Public API |
| SPU/Step Dependency | Step Composition to SPU contract only | SPU has no reverse package dependency on Step |
| Stage Result | Stage-owned and Stage-specialized | Generic envelope/schema remains unapproved; no Core Stage results package |
| Packaging | One distribution with dependency-free Core base and optional Prefect extra | Build backend/pinning and minimal Prefect transitive lock remain gates |
| Stage Callable | Runtime-independent contract remains required | Signature and invocation/result semantics unresolved |
| Public API Tests | tests/public_api/core/ and tests/public_api/integrations/prefect/ | Tests must verify supported exports, not private imports |
| Shared Contracts | Not established; no active dependency edge | Create only after demonstrated reuse, ownership and dependency closure |
| Pipeline Root | Consumer-owned Prefect Root Flow; no GPWCF Root Entity | Optional Pipeline Invocation Contract requires separate decision |
| Optional Result Slots | Typed contribution direction retained as a candidate | Final typing/serialization strategy remains open |
| Single Step Publication | Specialized capability; policy separated from mechanism | Concrete recovery/publication policy remains consumer-owned |
| Prefect Binding | Separate opt-in integration boundary | Production binding and failure/recovery qualification remain incomplete |

## 6. Closure verification

PHASE-03 acceptance establishes the logical module boundaries, package ownership, dependency directions, initial distribution shape and safe filesystem skeleton. It does not claim that unresolved contracts or production integration are implemented.

Remaining gates include:

1. Stage callable contract and signature.
2. Stage-specific Flow Result contract strategy.
3. StepExecutionResult optional result-slot typing.
4. Generic error vocabulary and conditional Step Error Model.
5. Concrete Single Step publication/recovery specialization.
6. Production GPWCF-to-Prefect functional binding and failure/cancellation/recovery qualification.
7. Minimal reproducible Prefect 3.9.2 transitive dependency lock.
8. Python build backend and build-system dependency pinning.

The initial filesystem authorization is limited to directories and minimal __init__.py package markers. It does not authorize placeholder implementations, speculative public exports or edits to specialized source contracts.


## 7. Detailed design-wave acceptance boundary

The 16 detailed design artifacts located under .docs/00.00_Primary_Architecture remain draft-for-architecture-review. Their proposed module additions (including core.identities and core.diagnostics), Stage/Step invocation/result envelopes, optional result contributions, SPU genericization, publication refinements, Prefect binding/operational mapping, exact Public API exports and packaging metadata are not accepted by the PHASE-03 closure.

The Packaging proposal currently recommends setuptools.build_meta with setuptools==84.2.1, gpwcf 0.1.0, Python >=3.15,<3.16 and py.typed. These remain proposal values, not approved project metadata. The accepted distribution-shape decision (one distribution, dependency-free Core base, optional prefect extra) is independent of those pending details.

The solution-level Python dependency asset location is SMRB/.dependencies/, with project-specific assets scoped beneath .dependencies/SMRB.GenericPipelineWorkflowComponentsFramework/. The shared developer interpreter remains SMRB/.env/ as documented in .dependencies/README.md.

Do not materialize source public_api package files, proposed identity/diagnostic modules, StageResult implementation, or build metadata until the relevant detailed design wave is explicitly accepted and PHASE-03 is reconciled again.
